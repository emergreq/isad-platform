# ISAD Hub

Платформа кафедры: React, Node.js и PostgreSQL. Локальный MVP обновлён 5 ноября 2026: библиотека с файлами, календарь, поиск с источниками в отдельном сервисе, профили, достижения и заявки на зачёт.

**Инструкция по возможностям, ролям и ограничениям: [docs/MVP-STATUS.md](docs/MVP-STATUS.md).** На главной студент видит занятия своей группы на сегодня, преподаватель — собственные предметы во всех своих группах. У онлайн-пар есть кнопка подключения. Совместные пары преподавателя показываются один раз.

## Запуск через Docker

Нужны Git и запущенный Docker Desktop (Linux containers). Для новой копии:

```sh
git clone https://github.com/emergreq/isad-platform.git
cd isad-platform
docker compose up --build -d
```

Только на **новой пустой базе** создайте демонстрационные учётные записи:

```sh
docker compose exec app npm run seed
```

Откройте <http://localhost:5173/>. API: <http://localhost:3000/>. PostgreSQL по умолчанию: `localhost:5433`, база/пользователь/пароль — `isad`. Внутри Docker адрес — `db:5432`. Локальный `compose.override.yaml` может менять порт БД.

Демо-почты: `student@example.org`, `headman@example.org`, `teacher@example.org`, `coordinator@example.org`, `student2@example.org`. Пароль: `demo-change-me`. Это локальная демонстрация; перед размещением в интернете нужны отдельные учётные записи и секреты.

На уже настроенном компьютере проект расположен в `C:\Users\LEDI\Desktop\isad-platform`: достаточно `docker compose up -d`; повторять seed и импорт не нужно. Рабочая база, загруженные учебные файлы и локальный `.env` не входят в Git. Новая копия получает код и демонстрационные данные; для переноса рабочей установки отдельно нужны резервная копия PostgreSQL и каталог `work/uploads`.

Поиск по материалам работает без ИИ-модели. Отдельный сервис помощника использует собственную базу; переменные для необязательной модели перечислены в `.env.example`.

## Что можно проверить

- Студент: расписание, свои занятия/ДЗ, личная отметка выполнения и её отмена, посещаемость, задолженности, самостоятельная запись на сдачу долгов, назначенные преподавателем пересдачи, материалы, заявки в проект.
- Староста: дополнительно журнал своей группы в пределах назначения, история исправлений, Excel за период полномочий.
- Преподаватель: создание и редактирование занятий/ДЗ своих преподаваний, отмена занятия без потери связей, журнал, задолженности, пересдачи и результаты, материалы с версиями.
- Координатор: пользователи, группы, состав и периоды членства, назначения старост, дисциплины и преподавания, контакты, публикация расписания.
- Автор проекта: создание проекта и позиций, принятие или отклонение заявок. Одновременные запросы на последнее место блокируются транзакцией PostgreSQL.

Учётные записи и учебные данные пока вымышленные. Реальное расписание доступно отдельно и не создаёт учётные записи преподавателей и студентов автоматически.

## Расписание

Источник: https://docs.google.com/spreadsheets/d/1pdaNyN6E758FPuXSMx9RQdSzUL_y1aZ15pzGuAS0up0/edit?gid=61443210

Подключены листы «2 курс», «3 курс», «4 курс» и шесть групп. Фильтры: курс, группа, подгруппа, верхняя/нижняя строка. Чётность недели и календарные даты не предполагаются. Дополнительные уточнения в тексте ячеек сохраняются.

Координатор нажимает «Проверить обновление», проверяет число записей и список групп, затем «Опубликовать версию». Все три листа читаются перед публикацией. Если источник недоступен или структура изменилась, последняя опубликованная версия остаётся доступной. Повторная публикация того же содержимого не создаёт новую опубликованную версию. Фоновое автоматическое обновление не включено.

Исходная таблица не изменяется. Учебное занятие с конкретной датой создаётся отдельно: это стабильная запись для ДЗ и посещаемости. Шаблон из Sheets не превращается в календарное занятие автоматически, поскольку источник не определяет календарь и значение верхней/нижней строки.

## Как менять проект

Код с компьютера подключён к `/app` контейнера через bind mount. React обновляется автоматически через Vite, API перезапускается через `node --watch`. При правке `package.json` или Dockerfile выполните:

```sh
docker compose up --build -d --renew-anon-volumes app
```

Флаг обновляет только том зависимостей приложения; именованный том `pgdata` базы сохраняется. Новые миграции в `db/` применяются при запуске приложения; после добавления миграции достаточно `docker compose restart app`. Уже применённые миграции не редактируйте — добавляйте следующий файл.

```sh
docker compose ps            # Состояние контейнеров
docker compose logs -f app   # Сообщения Vite/API; Ctrl+C выходит из просмотра
docker compose stop         # Остановить проект
docker compose start        # Запустить существующие контейнеры
```

`docker compose down` удаляет контейнеры, но сохраняет базу. **`docker compose down -v` удаляет том с базой** — для обычной остановки его не используйте.

## Проверки

```sh
docker compose exec app npm test
docker compose exec app npm run test:integration
docker compose exec app npm run test:mvp
docker compose exec app npm run build
```

Обычные тесты проверяют пароли, токены и разбор CSV. Интеграционные тесты создают отдельную временную БД, запускают отдельный API и проверяют права, историю журнала, содержимое XLSX, сохранность ДЗ при изменении занятия, конкуренцию за последнее место и публикацию расписания. Временная база удаляется после тестов. Рабочая БД не очищается. Пользователь БД должен иметь право создавать тестовую БД; локальный compose-пользователь его имеет.

## Резервное копирование и Git

```sh
sh scripts/backup.sh
sh scripts/check-backup.sh work/backups/ИМЯ-ФАЙЛА.dump
git status
git add client server db test scripts README.md package.json package-lock.json compose.yaml Dockerfile .dockerignore
git commit -m "Describe the change"
```

Проверка резервной копии восстанавливает её в отдельную временную базу, затем удаляет только эту копию. Рабочая база не перезаписывается. Резервные копии находятся в игнорируемой папке `work/`: они хранятся локально, а не в Git. Git сохраняет код; PostgreSQL хранит введённые через интерфейс данные. Локальный коммит сам по себе не отправляет код на GitHub.

## Архитектура и зависимости

`server/index.js` — HTTP, вход и базовые выборки; `server/features.js` — пользовательские сценарии и проверки прав; `server/schedule.js` — чтение фиксированных листов Google Sheets; `db/` — миграции; `client/src/` — React.

React/React DOM нужны для интерфейса, Vite — для разработки и сборки, `pg` — драйвер PostgreSQL. ExcelJS добавлен для настоящего `.xlsx` с листами «Посещаемость», «Сводка», «Сведения». Остальные задачи используют стандартные средства Node.js. Версии зависимостей зафиксированы lock-файлом, Docker использует `npm ci`.

Пароли хешируются scrypt, токены сессий хранятся как хеши, cookie — HttpOnly/SameSite. Авторизация выполняется в API. Для журнала состав группы и назначения проверяются на дату занятия. Для выгрузки староста должен иметь назначение на весь период. Процент: `(П + О) / (П + О + Н) × 100`; уважительные и неотмеченные исключены, отменённые занятия не экспортируются.

## Границы текущего выпуска

Одна активная роль на пользователя и одна группа на преподавание; для общего предмета двух групп создаются два преподавания. Материалы — версии метаданных и внешние ссылки, загрузки файлов и сдачи работ отсутствуют. Расписание — снимок источника и ручная публикация; полноценное сопоставление с календарными занятиями требует календаря семестра и правил кафедры. Результаты пересдач фиксируются однократно с историей; исправление уже выставленного результата — отдельный будущий процесс. Массового импорта пользователей, восстановления пароля, уведомлений и официальной ведомости нет.

Перед развёртыванием на реальных данных потребуются отдельные настройки HTTPS/секретов, правила кафедры и проверка безопасности. На момент установки `npm audit` сообщает 9 moderate предупреждений в транзитивных зависимостях ExcelJS (`minimatch`/`uuid` и цепочка архиватора). Приложение формирует XLSX в памяти и не принимает ZIP/XLSX либо glob-шаблоны пользователя. Принудительная замена на несовместимые версии не применялась; предупреждения следует пересмотреть перед публикацией.

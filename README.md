# ISAD Hub

Учебный портал на React, Node.js и PostgreSQL. Актуальная версия: 6 ноября 2026 года, миграции 001–017.

На главной студент видит сегодняшние пары своей группы, преподаватель — свои предметы во всех назначенных группах и подгруппах. Совместная пара отображается один раз. У онлайн-занятий есть кнопки подключения; отмены и переносы учитываются.

[Инструкция для сокомандников: запуск на другом компьютере](docs/TEAM-SETUP.md).

## Быстрый запуск

Нужны Git и Docker Desktop с Linux containers. Склонируйте проект:

```sh
git clone https://github.com/emergreq/isad-platform.git
cd isad-platform
```

Сначала создайте **локальные секреты**. При установленном Node.js 22+:

```sh
node scripts/init-local-secrets.js
```

Либо через Docker в PowerShell, без установки Node.js:

```powershell
docker run --rm -v "${PWD}:/app" -w /app node:22-alpine node scripts/init-local-secrets.js
```

Скрипт создаёт случайные значения в `.env` и не выводит их. `.env` не входит в Git и Docker image. Затем:

```sh
docker compose up --build -d
```

Дождитесь запуска API и Vite; состояние и сообщения доступны через `docker compose ps` и `docker compose logs app`. Откройте [портал](http://localhost:5173/); API — [localhost:3000](http://localhost:3000/).

Только для **новой базы без пользователей** создайте демонстрационные аккаунты:

```sh
docker compose exec app npm run seed
```

На уже настроенном компьютере seed и повторный импорт не нужны. Для обычного запуска достаточно `docker compose up -d`.

## Вход и приватные данные

Базовые демонстрационные логины: `student@example.org`, `headman@example.org`, `teacher@example.org`, `coordinator@example.org`, `student2@example.org`. Общего опубликованного пароля нет. Seed использует приватный `DEMO_PASSWORD` из локального `.env`; на существующем стенде ранее опубликованные пароли заменены индивидуальными.

Показать **свои локальные** логины и пароли в личном терминале:

```sh
docker compose exec app npm run accounts:show -- --reveal
```

Без `--reveal` команда не печатает пароли. Не публикуйте вывод и `.env`. В базе пароли хранятся как солёные хеши scrypt. Локальная таблица входа хранится в зашифрованном `work/private/accounts.enc.json` под отдельным `LOCAL_ACCOUNTS_KEY`. Этот ключ не передают другим участникам.

Реальные контакты, имена преподавателей, ссылки на занятия и адрес источника расписания исключены из открытого кода. Зашифрованный набор `work/private/teaching-data.enc.json` остаётся только локально и использует AES-256-GCM со случайным IV и проверкой целостности. Ключ `PRIVATE_DATA_KEY` хранится только в локальном `.env`, отдельно от Git. Новая копия Git не содержит этого набора. Если доступ разрешён, владелец отдельно передаёт зашифрованный файл и нужный ключ; их не публикуют в репозитории. Путь задаётся через `PRIVATE_DATA_FILE`.

После приватной настройки контакты можно импортировать:

```sh
docker compose exec app npm run import:private
```

На рабочем сайте контакты остаются доступны авторизованным пользователям по назначению справочника. **Защита файла в Git не означает шифрование всей PostgreSQL или загруженных учебных файлов на диске.** Рабочая база, `.env`, резервные копии и `work/uploads` хранятся локально и не входят в репозиторий. Новая копия Git не содержит введённых пользователями данных.

Удаление данных из текущей версии не стирает их из прежних коммитов и чужих копий репозитория. Опубликованные пароли нужно сменить; удаление персональных данных из истории — отдельная операция с переписыванием истории всех затронутых веток.

## Возможности

| Роль | Функции |
|---|---|
| Студент | Выбор группы и подгруппы, материалы по предметам и занятиям, календарь, домашние и курсовые работы, личная отметка выполнения, посещаемость, долги, проекты, достижения и заявки на зачёт |
| Староста | Дополнительно журнал и XLSX в рамках назначенной группы и периода полномочий |
| Преподаватель | Свои группы и предметы, совместные группы, занятия и ДЗ, переносы и отмены, анонсы, посещаемость, редактирование материалов, курсовые, форма контроля и условия закрытия, задолженности и результаты |
| Координатор | Пользователи, группы, членство и назначения, предметы, контакты, публикация версии расписания |
| Автор проекта | Проекты и позиции, рассмотрение откликов с ограничением мест |

### Материалы, задания и помощник

Материалы группируются по предмету и номеру занятия. Преподаватель добавляет файл или HTTPS-ссылку, меняет метаданные и номер занятия, прикрепляет дополнительные файлы, архивирует лишние и управляет публикацией. История правок сохраняется. Поддерживаются PDF, DOCX, SQL, DBML, YAML, TXT, MD и XLSX, до 25 МБ. Текстовые PDF и поддерживаемые текстовые форматы индексируются; OCR и извлечение текста из DOCX/XLSX не реализованы.

Домашние задания и курсовые со сроками видны в заданиях и календаре; курсовые также показаны в личном кабинете и содержат файл требований. Личные отметки выполнения не являются оценкой преподавателя.

Помощник ищет по доступным материалам выбранного предмета, учитывает ключевые слова, неполные слова и опечатки. Выдаёт ссылки на страницы документов. Поиск работает без ИИ-модели. Для генерации объяснений подготовлен адаптер; реальная модель пока не подключена, поэтому свободный диалог и качество ответов не заявляются.

### Долги и пересдачи

- **Сдача долгов:** преподаватель объявляет дату, место, число мест и список допущенных должников. Студент из списка записывается сам.
- **Пересдача:** преподаватель выбирает дату и студентов; назначения создаются автоматически. Самостоятельная запись на пересдачу недоступна.
- Даты попадают в календарь назначенного или записавшегося студента. Перенос и отмена сохраняют историю и вызывают уведомления.
- **Результат пересдачи:** преподаватель выбирает группу, отмечает сдавших и закрывает выбранные задолженности. У остальных долг сохраняется. Автоматическая итоговая оценка и исправление уже принятого результата не реализованы.

### Расписание и уведомления

Источник расписания задаётся приватным файлом или `SCHEDULE_SOURCE_URL` в `.env`. Поддержаны листы 2–4 курсов; выбранная версия хранится в базе. Координатор проверяет и публикует обновление. Если источник недоступен, последняя опубликованная версия сохраняется. Фонового обновления нет.

Верхняя/нижняя неделя выбирается явно: исходная таблица не определяет календарное чередование. Конкретные занятия для ДЗ и посещаемости создаются отдельно. Анонсы и изменения в расписании показываются за текущую неделю по Москве, остальные события остаются в календаре.

Один предмет может объединять несколько групп: у них общие материалы, занятия и задания. Староста получает доступ к журналу только своей группы. Уведомления внутри сайта содержат переходы к заданиям и событиям; интересы к проектам позволяют получать подходящие предложения. Email- и push-уведомлений нет.

## Архитектура и миграции

- `client/src/` — React; Vite — разработка и сборка.
- `server/` — HTTP, авторизация, файлы и API учебных сценариев.
- `assistant/` — отдельный сервис поиска и отдельная база знаний с отдельной ролью PostgreSQL.
- `db/` — последовательные миграции; `db/tests/` — SQL-проверки.
- `scripts/` — настройка секретов, демонстрационные данные, импорт и резервные копии.

Миграция **016** переносит проверки данных, части прав, статусы заявок, журналирование, уведомления и календарь в PostgreSQL. Миграция **017** защищает вместимость роли проекта при INSERT и UPDATE, включая конкурирующие переносы. Все правила доступа не сводятся только к SQL: API также проверяет авторизацию и разрешённые действия.

Реальные контакты из миграции 014 удалены при защите публичного исходного кода; её DDL сохранён. В существующей базе ранее импортированные контакты остаются. Новые контакты добавляются приватным импортом или через кабинет координатора.

`server/start.sh` применяет миграции, подготавливает базу помощника и запускает API/Vite. Уже применённые миграции обычно не редактируют — добавляют следующую. Состояние хранится в `schema_migrations`. Один откат Git не откатывает схему базы.

Основные зависимости: React, Vite, pg, ExcelJS и pdfjs-dist. ExcelJS формирует журнал XLSX; pdfjs-dist извлекает текст PDF. Версии фиксируются в `package-lock.json`, Docker устанавливает их через `npm ci`.

## Разработка и проверки

Код подключён к `/app` через bind mount. API использует `node --watch`; если Vite не увидел изменения файлов на Windows, перезапустите app. После изменения `.env` пересоздайте контейнеры, чтобы применить новые значения:

```sh
docker compose up -d --force-recreate app assistant
```

После изменения зависимостей или Dockerfile:

```sh
docker compose up --build -d --renew-anon-volumes app assistant
```

Для проверок нужен запущенный app и PostgreSQL с правом создавать временные базы:

```sh
docker compose exec app npm test
docker compose exec app npm run test:integration
docker compose exec app npm run test:mvp
docker compose exec app npm run test:db
docker compose exec app npm run build
```

Обычный `npm test` пропускает интеграционные наборы; для них используйте отдельные команды. Они создают изолированные базы и отдельные API, проверяют права, календарь, поиск, журнал/XLSX, заявки, переносы и конкуренцию за места. `test:db` дополнительно проверяет процедуры/триггеры и регрессию переносов участников. Рабочая база не очищается.

## Данные и резервные копии

PostgreSQL использует именованный том `pgdata`; учебные файлы — `work/uploads`. Для переноса рабочей установки нужны **обе базы** (`isad`, `isad_assistant`), файлы и секреты, переданные приватно. Дамп может содержать персональные данные — его нельзя коммитить.

Пример резервного копирования обеих баз в PowerShell без перенаправления бинарного потока:

```powershell
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
New-Item -ItemType Directory -Force "work/backups/$stamp" | Out-Null
docker compose exec -T db pg_dump -U isad -d isad -Fc -f /tmp/portal.dump
docker compose cp db:/tmp/portal.dump "work/backups/$stamp/portal.dump"
docker compose exec -T db pg_dump -U isad -d isad_assistant -Fc -f /tmp/assistant.dump
docker compose cp db:/tmp/assistant.dump "work/backups/$stamp/assistant.dump"
```

Сохраните `work/uploads` и `.env` отдельно в защищённом месте. Shell-скрипт `scripts/backup.sh` сохраняет только базу портала; `scripts/check-backup.sh` проверяет такой дамп через восстановление во временную базу, не перезаписывая рабочую. Шифрование приватного файла не заменяет защиту резервных копий.

Полезные команды:

```sh
docker compose ps
docker compose logs -f app
docker compose stop
docker compose start
```

`docker compose down` сохраняет именованный том. **`docker compose down -v` удаляет том с базами.** Для обычной остановки используйте stop.

## Ограничения

Нет университетского SSO, самостоятельного восстановления пароля, массового импорта пользователей, сдачи студентом файла работы, официальной ведомости, OCR и автоматической расшифровки записей. Контакты редактирует координатор. Авторизованные пользователи видят учебные данные в пределах реализованных правил доступа; HTTPS и серверное размещение требуют отдельной настройки.

В предыдущем аудите отмечены умеренные предупреждения в цепочке ExcelJS → uuid. Актуальное состояние проверяется командой `docker compose exec app npm audit --omit=dev`. Автоматический `audit fix --force` с несовместимой заменой ExcelJS не применялся.

Подробности реализации и отчёты: [MVP-STATUS](docs/MVP-STATUS.md), [проверка миграций 016–017](docs/REVIEW-db-concept7-2026-11-06.md), [план помощника](docs/AI-ASSISTANT-PLAN.md).

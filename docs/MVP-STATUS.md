ИСАД-101 и ИСАД-102 скрыты из выбора групп. БД, алгоритмы и практикум Python для БИВТ-25-6-1 и БИВТ-25-6-2 объединены: одна запись преподавания, общие занятия, ДЗ, материалы, ссылки, форма контроля и изменения. - Три счётчика на главной и подписи «Без отметки» удалены. ФИО в меню открывает личный профиль; полное имя редактируется в профиле и сохраняется для учётной записи.
- В «Проекты → Мои интересы → Настроить» выбираются направления и роли, затем включаются уведомления. Подходящий новый проект или добавленная в него позиция вызывает одно уведомление со ссылкой на карточку проекта. Если выбраны и направления, и роли, должны совпасть оба условия; внутри каждого списка достаточно одного совпадения. Уведомления можно отключить. Старые проекты при сохранении настроек не рассылаются, автор не получает уведомлений о собственных проектах. Подбор основан на названиях, описании и навыках, без ИИ-модели. Проверка новых уведомлений в открытом портале выполняется раз в 30 секунд и при возвращении во вкладку.
- В расписании анонсы ограничены текущей неделей по Москве: понедельник–воскресенье. На следующей неделе они уходят из блока, но сохраняются в календаре. Форма анонса в расписании рассчитана на текущую неделю; события на другие даты можно создать в календаре.
- Преподаватель видит недельное расписание групп, в которых у него есть преподавания. «Перенести занятие» доступно только у собственного предмета. Нужно подтвердить исходную дату и время, указать новые и причину. Для пары из недельного шаблона создаётся запись с конкретной датой; существующее занятие обновляется с сохранением идентификатора, ДЗ и посещаемости. Перенос показывается предупреждением у исходной пары и в блоке изменений; группе приходит уведомление с переходом на новую дату. Перенос на следующую неделю также остаётся предупреждением в исходной неделе. Исходный Excel не переписывается.
- В «Посещаемость» преподаватель выбирает предмет, группу и занятие. Если занятие ещё не создано, список группы уже виден; для отметок сначала нажать «+ Занятие». Кнопки «Присутствует» и «Отсутствует» сохраняют отметку сразу. Доступны опоздание, уважительная причина и снятие отметки. Исправления требуют причины и сохраняются в истории. Отменённое занятие не редактируется. Excel свёрнут в необязательную выгрузку.
- Форму контроля и условия закрытия преподаватель задаёт в карточке своего предмета на главной или в собственном профиле: «Форма контроля и условия». Варианты: экзамен, зачёт, зачёт с оценкой. Студенты видят сохранённые требования в карточке предмета. Чужие преподавания редактировать нельзя.

## Материалы и выбор группы

Материалы теперь разделены на предметы с отдельными заголовками и вкладками. Внутри предметов сохраняется группировка по занятиям. В календаре появился фильтр «Задания» и личные отметки выполнения домашних работ. Уведомления о новых и изменённых заданиях содержат переход к конкретной работе в календаре; ссылки проверяются по текущему доступу пользователя. Адреса вида `#calendar/homework-123?date=2026-11-10` открывают нужный период и выделяют карточку.

Поиск в помощнике использует ключевые слова, русскую морфологию, неполные слова и триграммное сходство для опечаток. Вопросы без точного совпадения всей фразы тоже ищутся. Результаты содержат названия и прямые ссылки на страницы; копии текста документов не выводятся и не возвращаются клиенту. Это поиск по источникам; свободные объяснения требуют отдельно подключённой модели. Подготовленный адаптер модели пока не проверен с реальным ключом. Неверная ссылка старого контеста у контрольной 13 ноября удалена; новая ещё не предоставлена. Ссылка контеста с дедлайном 6 ноября сохранена.

В библиотеке файлы объединены по предмету, группе и номеру занятия. Для БД занятие 1 содержит 4 файла, занятие 2 — 3, занятие 3 — 4. Презентация показывается первой. Поиск по одному файлу оставляет видимой всю подборку занятия. У методичек без номера занятия отдельные карточки. При загрузке преподаватель может указать номер занятия, чтобы новый файл попал в соответствующую подборку.

В «Мой профиль → Моя группа» студент и староста выбирают группу и подгруппу, затем нажимают «Сохранить группу». Группа сохраняется на сервере для учётной записи. Текущие преподавания, материалы, календарь, ссылки и доступные источники помощника обновляются по членству в выбранной группе. Сам выбор группы не создаёт для неё новые материалы и события: преподаватель добавляет их отдельно. Общие проекты, хакатоны и контакты остаются общими; собственная история оценок, посещаемости и заявок сохраняется.

Выбор группы в этом локальном прототипе самостоятельный. Прежние периоды членства сохраняются, изменение фиксируется в аудите. Исправление выбора в тот же московский день заменяет выбор этого дня. Полномочия старосты назначает координатор отдельно; выбор новой группы их не выдаёт. Подключение к реальной университетской системе потребует проверки принадлежности к группе.

Расписание студента показывается для его группы; подгруппа из профиля выбирается по умолчанию. Дни недели разделены на блоки, внутри пары отсортированы по номеру и показывают начало, окончание, преподавателя и аудиторию. Фильтр верхней/нижней строки сохранён без предположений о календарной чётности. Преподавателю и координатору доступен просмотр расписания разных групп.

В карточках регулярных пар добавлены «Подключиться» и «Записи занятий». Ссылка подбирается по предмету, группе и дню недели; правило конкретного дня имеет приоритет над общей ссылкой курса. Для БД используется постоянная ссылка, для Python — разные ссылки четверга и пятницы. Записи по этим ссылкам находятся на странице МТС Линк и могут требовать доступа.

Над неделей расположен блок «Анонсы и изменения» с опубликованными объявлениями, контрольными, сроками и занятиями с конкретной датой. Черновики студентам не показываются. Преподаватель своего предмета или координатор нажимает «+ Анонс занятия», выбирает предмет, дату, при желании время по Москве и ссылку, вводит текст и публикует. Этот же анонс появляется в календаре и уведомлениях группы. Анонсы относятся к конкретным датам и не меняют недельный шаблон.

## Запуск и остановка

1. Запустить Docker Desktop и дождаться работающего движка.
2. Открыть PowerShell в папке проекта:

```powershell
Set-Location 'C:\Users\LEDI\Desktop\isad-platform'
docker compose up -d
docker compose ps
```

Открыть <http://localhost:5173/>. Для уже настроенного компьютера повторный импорт или `seed` не нужны. Данные сохраняются в томе PostgreSQL и папке `work/uploads` после остановки и перезагрузки компьютера.

```powershell
docker compose stop
# Запуск после остановки:
docker compose up -d
# Диагностика:
docker compose logs --tail 80 app assistant
```

После изменения зависимостей собрать образ и обновить тома зависимостей обоих сервисов:

```powershell
docker compose up -d --build --renew-anon-volumes app assistant
```

После правок кода на Windows, если изменения не появились, выполнить `docker compose restart app`, затем обновить вкладку. Применение новых миграций выполняется при старте `app`. Для первой установки на другом компьютере нужны Docker, образ/интернет для сборки, начальный `seed`, затем отдельный импорт материалов или восстановление резервной копии. Один Git clone не переносит базу и загруженные файлы.

## Основные сценарии

**Студент.** В «Материалах» выбрать предмет и открыть оригинал. В «Помощнике» ввести тему, например «внешний ключ», «ряды», «разделяющиеся переменные»: появятся фрагменты и ссылки на конкретные страницы. Можно ограничить поиск одним документом. Блок ближайших сроков читает календарь портала независимо от модели. Личная отметка «Я выполнил(а)» не означает сдачу преподавателю.

**Преподаватель.** Войти своей демонстрационной учётной записью. «Мой профиль» показывает собственные предметы и группы, описание и навыки. В «Материалах» нажать «Загрузить материал», выбрать преподавание, название, тип и файл до 25 МБ. Поддерживаются PDF, SQL, DBML, YAML, TXT, MD и XLSX; презентации PPTX нужно предварительно экспортировать в PDF. PDF и текстовые исходники индексируются, XLSX хранится как файл. После загрузки нажать «Обновить», чтобы увидеть статус. Для сканов без текстового слоя нужен отдельный OCR, сейчас они доступны для скачивания.

События и контрольные создаются в «Календаре». Пару с конкретным временем сначала создать в существующем разделе «Задания». Для созданной пары в календаре можно задать ссылку подключения и отдельную ссылку записи, отменить занятие с причиной и необязательным заданием взамен. Замена постоянной ссылки не переписывает снимки других уже созданных пар; новые пары используют актуальное правило дня недели.

**Достижения и зачёт.** Студент добавляет личный вклад, GitHub и при желании сертификат PDF в карточке хакатона, затем отправляет заявку по выбранному предмету. Преподаватель этого предмета видит снимок доказательств и принимает решение с комментарием либо запрашивает уточнение. Одновременные решения защищены версией записи. Это решение внутри прототипа; официальная ведомость оформляется отдельно.

## Архитектура и ИИ

`app` содержит React/Vite и Node.js API. Основная база `isad` хранит пользователей, права и учебные записи. Сервис `assistant` и отдельная база `isad_assistant` хранят индекс документов, диалоги и источники. Там нет копий паролей и таблиц учебных заданий. Сервис получает разрешённые идентификаторы файлов от API после проверки текущего членства в группе; внутренние запросы подписываются HMAC. Порт сервиса помощника наружу не опубликован. Отказ помощника не останавливает календарь и библиотеку.

**Ключ модели не подключён.** Сейчас реализованы полнотекстовый поиск PostgreSQL и показ источников. Свободных объяснений, смыслового векторного поиска и дообучения модели нет. Сохраняется история запросов на сервере, но отдельный экран для просмотра старых диалогов ещё не реализован.

Подготовлен адаптер совместимого Chat Completions API. Когда будет выбран провайдер, заполнить локальный `.env` по `.env.example`: `MODEL_BASE_URL`, `MODEL_NAME`, `MODEL_API_KEY`. Ключ не писать в исходники и не отправлять в чат. Затем пересоздать контейнеры `docker compose up -d --force-recreate app assistant`. Конкретные параметры авторизации провайдера и качество ответов требуют отдельной проверки с реальным ключом. При включённой модели найденные фрагменты будут отправляться провайдеру; сейчас обработка учебных файлов локальная.

## Ограничения текущего выпуска

Это локальный прототип, без публичного размещения и университетского SSO. Отдельной публичной страницы преподавателя с контактами и расписанием консультаций нет; есть личный кабинет и рабочие функции роли. Нет OCR, автоматической расшифровки записей, автоматического импорта из МТС Линк и почтовых/push уведомлений. Уведомления отображаются внутри сайта. Формулы нужно сверять с оригиналом PDF. Загрузка новой редакции через библиотеку создаёт отдельную карточку материала; интерфейс замены файла с полной историей редакций ещё не добавлен. Обновление недельного расписания из XLSX выполняется подготовленным импортом; автоматического наблюдения за исходным файлом нет.

Демонстрационные пароли и значения секретов подходят для локальной разработки. Публичное размещение требует отдельной настройки доступа, секретов, HTTPS, резервных копий и проверки с реальными пользователями.

## Резервная копия

Код в Git и учебные данные хранятся отдельно. Папка `work/` игнорируется Git. Для переноса нужно сохранить обе базы и оригиналы файлов. Предварительная копия основной базы перед внедрением находится в `work/backups/isad-before-mvp-20261104.dump`.

Из папки проекта выполнить в PowerShell:

```powershell
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$backupDir = Join-Path (Get-Location) "work/backups/$stamp"
New-Item -ItemType Directory -Path $backupDir -Force
docker compose exec -T db pg_dump -U isad -Fc -f /tmp/isad.dump isad
docker compose exec -T db pg_dump -U isad -Fc -f /tmp/isad-assistant.dump isad_assistant
docker compose cp db:/tmp/isad.dump "$backupDir/isad.dump"
docker compose cp db:/tmp/isad-assistant.dump "$backupDir/isad-assistant.dump"
Copy-Item -LiteralPath work/uploads -Destination "$backupDir/uploads" -Recurse
```

Копировать оригиналы лучше при остановленной загрузке файлов, чтобы копия базы и файлов соответствовала одному состоянию. Восстанавливать сначала на отдельной установке. `docker compose down -v` удаляет том базы — для обычной остановки использовать `docker compose stop`.

Подготовленный импорт находится в `scripts/import-course-materials.js` и читает локальный `work/course-import/manifest.json`, файлы и CSV. Повторный запуск `docker compose exec -T app node scripts/import-course-materials.js` использует стабильные ключи импорта; исходный комплект должен оставаться на месте. Для обычного запуска сайта импорт не нужен.

В GitHub изменения автоматически не отправлены. Для ревью сначала проверить `git diff` и `git status`; базу, материалы и `.env` в коммит не добавлять.

### Актуальные сценарии пересдач и сдачи долгов, главная — 05.11.2026

# Запуск ISAD Hub на другом компьютере

Это инструкция для отдельной локальной копии проекта. У каждого разработчика будет своя база, свои секреты и свои пароли. Данные из другой локальной копии автоматически не синхронизируются.

## 1. Подготовка

Установите Git и Docker Desktop, запустите Docker Desktop и используйте Linux containers. Выберите папку, где хотите хранить проект, и откройте в ней терминал.

```sh
git clone https://github.com/emergreq/isad-platform.git
cd isad-platform
```

## 2. Создание собственных секретов

Если установлен Node.js 22+:

```sh
node scripts/init-local-secrets.js
```

Если Node.js не установлен, выполните в PowerShell:

```powershell
docker run --rm -v "${PWD}:/app" -w /app node:22-alpine node scripts/init-local-secrets.js
```

На macOS/Linux в обычном терминале:

```sh
docker run --rm -v "$PWD:/app" -w /app node:22-alpine node scripts/init-local-secrets.js
```

Будет создан `.env` со случайными локальными секретами. Он не публикуется в Git. Не берите общий пароль из старых инструкций и не копируйте чужой `.env`: там могут быть ключи и пароли, которые вам не нужны.

## 3. Запуск

```sh
docker compose up --build -d
docker compose ps
docker compose logs --tail=60 app
```

Дождитесь сообщения `API listening` и запуска Vite. При первом запуске автоматически применяются миграции, создаются две базы: портал и сервис поиска. Создайте демонстрационных пользователей только на новой базе:

```sh
docker compose exec app npm run seed
```

Если seed пишет, что база уже содержит пользователей, повторять его не нужно.

Откройте [http://localhost:5173/](http://localhost:5173/). API находится на порту 3000, PostgreSQL по умолчанию — на 5433. Внутри контейнеров PostgreSQL доступен как `db:5432`.

## 4. Где взять свой пароль

Выполните только в личном терминале:

```sh
docker compose exec app npm run accounts:show -- --reveal
```

Команда показывает локальные аккаунты этой копии. Без `--reveal` пароли не печатаются. У чистой демонстрации доступны студент, староста, преподаватель, координатор и второй студент. Эти аккаунты не являются аккаунтами GitHub и не дают доступ к чужому компьютеру.

Если `.env` утерян, зашифрованные локальные файлы без ключа прочитать нельзя. Храните ключи в защищённой резервной копии.

## 5. Что будет в новой копии

Код, схема базы, тесты и демонстрационные данные после seed. Реальные PDF, введённые на другом компьютере задания и оценки в Git не хранятся. Реальные контакты, имена преподавателей, ссылки занятий и адрес источника расписания хранятся только локально в зашифрованном файле, которого нет в Git. Собственный новый ключ не расшифрует чужой файл.

Для разработки интерфейса достаточно демонстрации. Координатор может создать группы и предметы, преподаватель — добавить материалы и занятия. Отсутствие реального расписания и контактов на чистой копии ожидаемо.

Если вам разрешён доступ к реальному приватному набору, владелец отдельно передаёт зашифрованный файл `work/private/teaching-data.enc.json` и нужный ключ по личному защищённому каналу. Укажите его в локальном `PRIVATE_DATA_KEY` и задайте `PRIVATE_DATA_FILE=work/private/teaching-data.enc.json`, затем:

```sh
docker compose up -d --force-recreate app assistant
docker compose exec app npm run import:private
```

Ключ шифрования и пароль входа на сайт — разные значения. Ключ `LOCAL_ACCOUNTS_KEY` защищает только ваш локальный список паролей — не передавайте и не меняйте его без повторного шифрования списка. Он не зависит от `PRIVATE_DATA_KEY` учебного набора. Для полной копии учебных данных нужен согласованный перенос баз и `work/uploads`, который владелец выполняет отдельно; для обычной разработки такой перенос не требуется.

## 6. Проверки и обновление кода

```sh
docker compose exec app npm test
docker compose exec app npm run test:integration
docker compose exec app npm run test:mvp
docker compose exec app npm run test:db
docker compose exec app npm run build
```

Интеграционные проверки создают отдельные временные базы. Перед обновлением рабочего стенда сохраните свои базы и загруженные файлы. Проверьте локальные изменения через `git status`; затем получите согласованные изменения команды. После обновления кода и зависимостей:

```sh
docker compose up --build -d --renew-anon-volumes app assistant
```

Миграции применяются при запуске app. После изменения только `.env` достаточно пересоздать app и assistant с `--force-recreate`.

## 7. Остановка и типовые проблемы

```sh
docker compose stop
docker compose start
```

Не используйте `docker compose down -v` для обычной остановки: флаг `-v` удаляет базы.

- Docker не отвечает: запустите Docker Desktop и дождитесь готовности движка.
- Порт 5433 занят: задайте другой внешний порт PostgreSQL в локальном `compose.override.yaml`. API продолжает использовать внутренний `db:5432`.
- Не принимается пароль из старого чата: используйте локальный список этой установки, а не чужие или старые пароли.
- Приватный файл не расшифровывается: проверьте соответствие ключа именно этому файлу. Не публикуйте ключ и сам вывод ошибки вместе с содержимым `.env`.
- Не видно изменений интерфейса: обновите страницу через Ctrl+F5, при необходимости перезапустите app.

Если команда использует один размещённый сайт, у каждого участника должна быть отдельная учётная запись на этом сайте. Пока проект работает на отдельных localhost, базы и пользователи у участников независимые. Общая серверная версия в этом репозитории автоматически не разворачивается.
